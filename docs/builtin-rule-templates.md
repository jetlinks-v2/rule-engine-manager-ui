# 内置规则模板与快速创建

## 创建流程

规则列表的「新增」打开内置模板目录。模板提供自然语言名称、说明、静态流程图和独立节点 ID，不再要求先填写名称。创建复用 `POST /rule-editor/flows/_create`，默认禁用，成功后打开现有编排编辑器。

- 无业务参数的模板直接创建；设备来源、字段等可在创建前选择，也可点击「稍后配置」。
- 配置保持轻量。产品、设备下拉展开时加载首批选项；输入搜索防抖 250ms，每页 20 条，滚动追加。选项同时显示名称和标识，以区分同名资源。
- 左侧采用紧凑的标签与控件同行布局，范围和消息类型使用分段选择。表单模型绑定实际选择值；提交校验与编辑时的错误恢复共用业务校验，不能保留已经修正的必填提示。
- 先选产品，再展示设备范围、消息和物模型字段；周期使用常用时长选择。复杂认证、连接、通知和设备动作沿用节点自己的配置面板。
- 跳过配置会丢弃尚未完成的业务参数，创建禁用流程骨架。缺失来源保留空 SQL 或空设备消息，不扩大成所有设备、不填造字段，也不部署或触发动作。
- 创建中禁止重复提交；失败保留选择，取消不创建规则。

## 目录与配置边界

| 分类 | 模板 | 创建前可选内容 / 后续配置 |
| --- | --- | --- |
| 数据转发 | 转发设备数据 | 单产品全部设备或指定设备、属性/事件、发送格式、HTTP/MQTT/Kafka 目标；连接和认证在节点中配置 |
| 数据转发 | 汇总数据后转发 | 设备范围、数值属性、汇总时长与方式、转发目标 |
| 数据整理 | 统一设备数据格式 | 设备范围与属性，可附带属性元数据；输出逐属性记录 |
| 数据整理 | 处理数据并返回结果 | 规则输入 → 函数 → 规则输出，无必填参数 |
| 数据整理 | 一次返回多项结果 | 规则输入 → 并行 → 两个有限处理分支 → 聚合 → 规则输出 |
| 数据查询 | 查询设备信息 | 提供请求与返回骨架，进入命令节点选择真实服务、命令和参数 |
| 数据查询 | 同时查询设备信息与属性 | 提供双分支查询与聚合骨架，具体查询仍在命令节点中配置 |
| 设备操作 | 定时读取设备属性 | 单设备、可读属性和常用周期；可全部跳过 |
| 设备操作 | 设备发生事件时执行操作 | 来源范围与事件；目标设备及动作在设备消息节点中配置 |
| 异常提醒 | 设备数据超限时提醒 | 数值属性、比较条件和阈值；通知渠道在通知节点中配置 |
| 入门示例 | 手动处理一条数据 | 规则输入 → 函数 → 规则输出，同时连接调试输出 |
| 独立入口 | 自定义规则 | 从空白开始 |

目标类型按实际安装节点展示。缺少所需节点时禁用对应模板并说明原因；组件目录读取失败可重试。

## 设备与流程契约

- 产品全部设备使用运行时 topic 范围；指定设备保留明确 ID 和产品归属，不能混成扩大后的范围。首版处理单产品，不另建组织、标签或多产品的范围解释器。
- 完整属性消息转发不额外读取物模型。选择属性、事件或统计时读取完整定义；指定设备使用自身模型，多设备只保留标识、结构、类型和单位兼容的字段。
- 支持完整消息、选定字段对象、逐属性记录；事件读取 `data`，属性读取 `properties`。SQL 标识和字面量分别转义，数值汇总与阈值检查真实字段类型。
- HTTP/MQTT 适配对应消息结构；固定 topic 的 Kafka 直接发送业务对象。未完成的资源、连接和通知配置由编辑器继续承接。
- 每次创建独立节点、连线和聚合 mapping。`zip-output.mapping` 指向直接上游分支终点，返回键保持 `data`/`summary` 或 `deviceInfo`/`propertyResult` 等稳定数据字段。
- 请求响应分支必须有限完成。`flatWhenSingle=true` 只展开单条结果，多条仍是数组；空分支不自动补字段。不得把骨架创建成功当成查询、通知或设备动作执行成功。

## 图例与国际化

`assets/rule-templates/*.svg` 是提前导出的 Node-RED 图例，包含固定几何、节点类型和连线。模板目录不启动 iframe、隐藏画布或运行时布局器；只替换 `{{source}}` 等文字占位符并做 XML 转义。HTTP、MQTT、Kafka 使用各自的静态图例。

共用流程工厂将当前语言及目标类型的静态图例写入 `metadata.thumbnailSvg`，与规则在同一次创建请求中保存，列表首次读取即可显示缩略图。页面、智能体及跳过配置均沿用此契约；空白规则没有虚构流程图。后续编辑保存继续由现有画布缩略图更新链路接管。

静态图例只保留节点、图标与连线，不携带导出时的校验角标、运行状态或修改标记。所有模板同时写入语义匹配的 `metadata.icon`，空白规则使用编排图标；历史规则没有配置图标时沿用默认值。列表从已有可见范围预览请求读取图标，不扩大摘要查询或另发全量详情请求。

编排头部的名称、说明使用平台 `InputEditable` 的单行模式，长内容省略展示，Enter 或失焦提交、Esc 取消，标题栏不随输入增长；图标使用支持紧凑尺寸与异步回执的 `IconLibrary`。字段保存失败保留草稿；文字请求只提交对应字段。图标和画布缩略图更新在客户端串行合并最新 metadata，保留彼此及其他展示字段。

中英日覆盖分类、标题、说明、选择项、提示、图例及生成节点名称。创建后的名称与说明按当前语言保存，带入已经明确选择的对象和条件；切换语言不会改写已保存规则或业务 ID、SQL 和返回字段。静态图例与流程工厂的节点、连线一致性由测试覆盖。

## 编辑定位与智能体

创建后优先定位待配节点，完整配置则定位主要处理节点。桥接可以在空画布阶段就报告就绪，因此初始化同时等待 iframe 加载和流程节点出现，再定位一次；用户已有选中节点时不抢焦点。定位复用 `rule_editor_focus_node`，不会模拟双击或自动打开配置面板。

创建结果通过现有路由参数交接保留首次定位信息，避免查询参数导航重建页面时丢失初始化或重开创建面板。智能体使用相同模板目录和流程工厂；需要业务参数时打开同一个面板，后续复杂配置仍交给现有编辑器工具。

ReactorQL 复用设备 owner 的 `JetLinksRuleEditorThingResources.search`。通过 `definitionIds` 与 `includeSchema` 读取选中字段的完整单位、枚举、嵌套类型和事件 outputs；缺少主体、字段缺失、截断或元数据格式错误不能冒充完整模型。

## 验证与限制

卡片名称单行省略、右侧操作对齐及底部状态的启停确认沿用列表契约。

定向验证覆盖独立身份与连线、创建请求携带缩略图、静态图例、多语言、XML 转义、范围切换、延迟加载、分页、跳过、失败重试、校验恢复与路由重建交接。前端命令为 `pnpm test:rule-templates`、`pnpm test:instance-list`、`node scripts/run-agent-tool-tests.mjs`；设备 owner 的完整 schema 测试位于 `modules/device-manager/src/test/js/rule-editor-thing-resources.test.mjs`，ReactorQL 委派与多语言测试位于 `modules/jetlinks-components/rule-engine-component/src/test/js/reactor-ql-resources.test.mjs`，均可在所属仓库用 `node --test` 独立执行。

表单回归已在真实宿主验证：产品、指定设备和目标参数读取同一份响应式值，避免控件 change 校验读取上一帧的模型。清空设备显示必填提示，重新选择后自动消失；提交时的业务错误随参数修正重新校验，请求失败不被这一过程吞掉。英文配置标签保持单行，左侧无横向溢出。

内置浏览器已核验真实产品搜索、设备下拉、跳过后创建禁用草稿、加载后自动选中节点、中英日图例、680px 单列配置和列表滚动归属。新增「手动处理一条数据」后，未点击编辑器保存即关闭，列表从后端读取的 SVG 缩略图成功显示。验证仅创建禁用草稿，未发布或触发设备动作。
