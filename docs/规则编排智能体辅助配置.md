# 规则编排智能体辅助配置

规则助手根据当前可用节点的 owner 契约组合规则，只修改未保存草稿，不替用户保存、发布、启用或执行规则。

## 架构与边界

```text
业务能力：RuleGoal -> ResolvedRulePlan
原生节点：TypedCanvasPlan
                     -> PreparedCanvasPlan -> CanvasApplyReceipt
```

| 所有者 | 职责与入口 |
| --- | --- |

## 工具与路径选择

- capability catalog 能表达业务目标时，使用 `rule_editor_orchestrate_goal`；目录不能表达，或目标明确涉及原生节点、流处理、转换、脚本、聚合时，使用原生计划。
- 原生模型工具面仅包含画布读取、节点搜索、类型详情、目录、手册、owner 只读辅助工具、`rule_editor_apply_canvas_actions` 和校验。非法工具不执行；业务阶段存在已暴露合法工具时复用现有有界改选，terminal/closed 阶段不扩工具面。模型不直接调用逐节点 insert/edit/delete/connect/layout 或内部 prepare。
- 新增独立流程只读取所选类型及所需领域事实；修改、复用或诊断已有节点时，才读取对应画布节点及最新配置。
- 节点类型来自搜索结果的 `nodeTypes[].type`，写入 `steps[].nodeType`；画布节点 ID 来自实际画布读取，两者不能互换。
- 旧画布中没有 owner 声明的节点可作为不透明拓扑事实保留，但不能由助手搜索、新建、修改或调用其辅助工具。
- 共享领域工具按页面权限和只读声明准入，生命周期属于规则父页。iframe 卸载或握手失败只撤销画布传输；页面仍有效时，共享只读事实工具继续经自己的 runtime 执行。父页关闭后停止两类工具，旧 handler 不执行任何效果。

真实业务歧义才需要用户选择。缺少节点类型、平台 ID、字段或配置等实现事实时，由工具取证，不要求用户提供内部实现。通知、存储或返回去向未明确且影响业务结果时，先询问一个必要业务问题，不擅自补终点。

## Owner 与数据契约

### Capability

业务能力由 owner 显式声明：

```text
capabilityId + localizedName / localizedDescription
effect: READ | WRITE
inputContract / outputContract
bindingTemplates
metadataResolver（需要平台发现时）
semanticDescriptors（可选）
discoveryHintPolicy
```

- capability 按真实 catalog ID、业务语义、effect 和输入契约选择，不从 intent、节点名称或路由合成 ID。
- 非法条目及重复 ID 的冲突组排除，不连带清空其它合法能力；截断、目录失败与候选自身失败分别报告。
- `RuleGoal` 只表达 flow、inputs、intent、capabilityRef、bindings 和期望 output，不包含节点私有配置、坐标、steps 或 prepared handle。
- 输入名和 operation 输出名使用稳定 ASCII 符号；intent、说明与搜索提示使用用户语言。平台 ID、字段名和字面量不翻译。
- bindings 只引用已声明的 `$input.<name>` 或 `$<operationOutput>`；引用输出子字段必须有 owner 契约依据。
- 返回字段保留用户指定名称，不额外回显输入。完整请求或消息对象优先整体绑定，不擅自拆成标量字段；未知类型保持 unknown，已知契约冲突仍拒绝。

### 字段与命令事实

- 依赖领域字段的配置先读取真实产品或设备物模型。字段 ID、类型、单位及访问模式来自用户明确的标准 ID、owner/上游契约或真实元数据；自然语言只用于检索。
- 调用方提供的运行时参数直接按输入契约引用，不拿当前规则或页面 ID 代替参数查询资源目录。SQL/脚本别名不能反向作为源字段证据。
- 命令搜索只返回候选摘要和 `detailArguments`；已选候选的字段、必填性、枚举及嵌套结构通过同一 owner 工具按 `serviceId + command` 精确读取。
- `metadataComplete=false` 不构成完整 schema 证据。无关服务失败只说明目录覆盖不完整；已选 owner 失败或必需 schema 缺失仍阻止配置。
- 常用命令描述由命令节点 owner 补充业务含义，运行时 metadata 确认实际能力，不向共享层增加业务词表或命令白名单。
- 查询条件在真实 metadata 支持时优先使用 `filter: map`，排序使用独立 `sorts`；旧 owner 仅按实际输入契约处理，不补造字段。
- 动态命令通过上游构造完整 `{serviceId, command, parameter}` envelope，并使用 `source=upstream`。固定模式只接受真实字面量，不解释字符串占位符。

## 渐进披露与缓存

- 搜索摘要仅保留身份、用途、端口和详情入口，不带配置与统计计数。类型详情保留最小节点契约；既有 catalog query 支持多个关键词与省略 section 后跨 owner 已声明分类读取，manual query / section 支持按需章节及子章节，不新增强制逐字段发现流程或批查询工具。completion 的公开与编译 schema 共用模式约束：partial-draft 仅接受 mode，complete-topology 必须含非空 sources / terminals。
- 节点搜索返回身份、用途、端口及详情入口；组合搜索返回成员角色和 continuation，完整 slots/configure 通过类型详情的 `compositionId` 补读。
- 默认类型详情保留可写字段、必填性、输入输出、关键 `aiAgent` 运行事实和定向读取入口，不自动加载目录匹配、模板 SQL 预览或重复正文。
- catalog 摘要保留 `id/title/description/sections` 与 `detailArguments: {type, catalogId}`；manual 摘要保留 `id/title`、按既有 180 字符规则截断的 owner description 与 `detailArguments: {type, manualId}`。两类资源即使 ID 相同也属于不同读取入口，不猜测别名或混用参数。函数签名和手册正文仍按需读取；没有可达目录或手册的扩展节点保留有界 help 摘要。
- 节点搜索按真实 responseId 与完整规范化参数复用结果，不限制合法的不同角色搜索。缓存回放保留真实 payload、覆盖度和可解析绑定，不伪造 success、reused 或完整性。
- owner 只读工具仅复用同参数的完整成功结果；失败、异常和不完整结果可重新取证。写操作及结果未知时使旧查询事实失效。
- profile 在同一 responseId 内复用同参数类型详情、目录页和完整手册片段；详情中的模板和手册排序仍受 keyword 影响，不把不同 keyword 的请求合并为缓存命中。画布写入使配置相关 owner 查询失效，仍有效的类型资源保留。截断手册、显式失败和不完整结果可重读，不把摘要或分页覆盖升级为完整事实。
- 查询改变后沿新结果 cursor 分页，不复用旧查询的页码。摘要、失败或缺失结果路径不能声明为完整证据或有效 outputBindings。
- 已取得必要事实后直接生成计划；预检失败只补诊断指向的缺口，不通过换词搜索、重复手册或无关角色浏览代替修复。

## 计划、确认与提交

模型提交一个结构化计划，客户端持有内部 prepared handle：

```text
prepare（零写入） -> 本地确认 -> apply -> receipt verify
```

- `PreparedCanvasPlan` 绑定 editor session、base revision、requestId、planDigest、expiry 及编译后的计划。模型不得生成或复制 preparedPlanId/planDigest。
- steps/completion 保持结构化；未知字段按公开 schema 拒绝。引用明确区分现有 `node-id` 与本计划较早插入的 `alias`。
- 原生计划可使用完整 composition 或手写节点/连线；不在同一计划混用两套展开方式。配置读写由 owner 适配器负责，不绕过编辑器直接改规则实例数据。
- 确认卡展示业务摘要、预计变更、基础 revision 和“仅写入未保存草稿”，不暴露内部句柄或私有配置。
- session、revision、digest、expiry 或 requestId 不一致时零写入；提交遵守原子应用和回滚契约。
- 确认拒绝、执行前取消或失败时释放 prepared 状态。响应丢失或效果未知时先只读核验，不盲目重放 apply。
- 幂等由 logical call、requestId、prepared handle 及目标一致性负责，不设置 applied 后的整轮工具锁。部分写入后允许读取最新 revision/configDigest 并增量修复，不重复插入已写入节点。
- 普通脚本不强制携带生成器 bindingEvidence；沿真实 owner 输出及连接契约校验，已知缺少下游必需字段仍拒绝。

## 原生保存与发布

保存、发布由原生编辑器执行，桥接层只等待真实完成事件及错误结果。嵌入模式隐藏头部，不能用头部遮罩是否可见、遮罩消失或短时间内没有 UI 变化判断“没有更改”或执行失败；请求尚未返回时保持等待，不自动重试或延长现有超时。

提示按动作所有者划分：保存、发布的业务结果由原生编辑器提示，父页只保留失败状态并恢复按钮，不重复弹窗。实现去掉跨层“已提示”标记，兼容旧 iframe 的错误回执；原生等待超时及未处理异常仍在编辑器内提示，父页只提示通信超时、连接失效及自身缩略图同步问题。不按错误文案去重，不新增状态机或通用通知中心。集中验证新旧回执、失败不转成功、异常提示及等待器清理。

调用前遵守原生按钮禁用状态，完成后释放事件监听与轮询；不改后端保存/发布接口、节点校验或运行规则。保存等待回归覆盖隐藏头部且响应超过 300ms、慢响应后成功、实际错误、既有 55 秒超时及等待器清理。外层提示修复兼容旧回执，原生等待修复须加载更新后的后端静态资源。只读检查已确认运行中 iframe 仍使用旧脚本，未对当前规则执行保存或发布，在线交互尚待资源更新后复验。

## 完成与进度

拓扑完整、配置可写、画布已修改和业务目标完成是不同事实。

- `complete-topology` 验证目标要求的完整边界；`partial-draft + targetState=configured` 只证明局部配置，不自动满足原始完整目标。
- 原生 fallback 通过 `ruleEditorAgentProfile.ts` 复用 `mergeRuleEditorTaskTarget`，合并已有可信目标与 fallback 的 required checks，保留 topology / execution 等已有义务；没有可信目标时仍默认完整目标。增量修复不降低目标，只有现有本地明确确认路径可以减少校验；真实业务问题及 awaiting-input 回执优先保留。
- 请求响应的每个入口必须可达匹配的响应出口，允许合法副作用旁路；双方声明 requestContext 时检查匹配，不因旧节点缺少该字段增加版本门槛。
- 自包含实时节点按 owner 边界判断，不为凑终点追加日志、透传或请求响应专用出口。
- ReactorQL owner `11-reactor-ql.html` 仅在 stream=1、已识别 SQL 数据源来自独立 Topic（可含 dual）、且不含 all / 具名上游 / 不确定来源时声明 completionTerminal；真实 runtime 同时发出 result 事件并写 output。FROM 列表取证跨越 JOIN 的 ON 条件，条件后的同层逗号来源仍须纳入判断，无法证明的来源保守保持 uncertain。`complete-topology` 可将同一节点作为 source / terminal，应用仍依赖可信 snapshot，当前画布复验按真实 owner 可达性接受零连线。普通上游转换、请求响应及明确要求的下游业务动作保持各自边界，不按节点类型或用户文本豁免，不通过 `configured` 降低已有完整目标。

父页验证 `CanvasApplyReceipt` 的 mutation、verification、taskProgress、revision 和实际变化：

| 事实 | 结果 |
| --- | --- |
| applied 且原目标的可信必需检查满足 | completed |
| applied 但证据缺失或目标未满足 | partial；必须说明草稿已修改 |
| not-applied 且确有业务问题 | awaiting-input |
| not-applied 且无业务问题 | blocked / failed |
| rolled-back | failed，说明已回滚 |
| unknown 或 effect 与 mutation 冲突 | 不声明成功，先只读核验 |

只为真实存在的结果分支发布 outputBindings，显式 incomplete 不升级为 complete。最终答复据回执简述实际变更及未决项，不能把工具成功、模型文案或局部计划检查当作整轮成功；草稿写入不等于保存、发布或执行。终答模型超时保留未恢复必需工具的安全诊断，执行状态仍为 `FAILED`，未知写效果不升级为成功。

用户摘要由 `toolRuntime.ts` 的可信 mutation / completion / taskProgress 生成，作为 `claims.role=summary` 发布；label 复用当前语言的业务工具名称。模型修复用的原始 instruction 保留在结构化字段中，不经敏感词清洗后变成用户正文。applied 但目标未满足时，摘要说明草稿已修改、未完成检查及尚未保存或发布；共享 claim 类型与投影须保留可选 summary role。

进度来自真实 provider 和 prepare/apply/verify 生命周期，使用通用 `client-tool-progress/v1`；取消、超时、重置及销毁向 iframe 和 owner 传递 signal/deadline，不生成虚假阶段或人工延时。不可用结果使用 `rule_editor.bridge.unavailable` / `rule_editor.shared_tool.unavailable`，`details.bridge` 只含生命周期原因、桥接状态及 frame/origin 可用性；未发请求声明 `not-started / not-applied`，已发请求丢失结果保留效果未知，禁止自动 apply/replay。共享 owner 分发不代替当前权限准入，也不映射未知工具名。

## ReactorQL 与扩展节点

ReactorQL 的具体语法、函数签名、数据源和模板由节点 owner 目录及手册维护，本文件不复制函数清单或业务配方。

- 使用真实运行时支持的函数，聚合过滤复用 select 的结果别名，不套用其它 SQL 方言。
- 时间窗口负责分组生命周期时，先建立时间窗口，再在窗口内按业务 key 分组；普通 group by 和每 key 条数窗口不机械重排。
- 订阅范围由真实领域事实限定，物模型字段不得猜测；配置/绑定检查通过不等于实际数据和运行结果正确。
- 告警已持久化、通知资源兼容性、消息总线与存储配置等事实由各自 owner 提供；共享 profile/bridge 不增加具体场景分支。
- 新节点接入先声明真实配置、端口、运行边界及取证入口；注册为普通编辑器节点不自动获得助手写入能力。

## 声明准入与上下文

通用后端的 `ToolContractAudit.java` 以 `ToolArgumentSchemaValidator.inspect` 判断标准 JSON Schema 形式合法性。`required` 不必在同层 `properties` 中重复声明，组合与条件分支可以约束外层字段，开放对象也可以要求未枚举字段。缺少描述、开放对象等最佳实践问题只产生有界诊断；非法 Schema、受限引用、根参数对象约束、权限、业务效果和运行时自有参数仍遵守既有准入边界。形式合法不代表业务配置或调用参数正确，执行校验、completion 模式、预检、确认和回滚继续生效。

真实前端契约由以下链路导出，不在 Java 测试中手工复制 Schema：

```text
ai-agent-canvas-plan-contract.js 的 apply / prepare inputs 与 expands
  -> ruleEditorAgentProfile.ts / toRuleEditorClientToolDefinition
  -> clientToolCatalog.ts 的 createAiClientToolCatalogSnapshot().wireDefinitions
  -> ai-agent-general/src/test/resources/rule-editor-client-tools.json
  -> RuleEditorToolContractRegressionTest
     （CommandJsonSchema / ToolBinder / LoopToolContext / 普通模型请求）
```

fixture 使用 `rule-editor-client-tools/v1` envelope，`tools` 保存 orchestrate 与 apply 的完整 wire definition，包括 `expands._schema` 和真实 WRITE effect。profile 存在内部 prepare 时，公开 apply 使用结构化计划 Schema，prepared handle 仍由客户端持有。`tests/ruleEditorClientToolWire.test.ts` 同时核对原始 iframe adapter、profile 发布面和共享序列化；默认测试重新生成内存 payload 并与 fixture 完整比较，只有显式导出命令更新文件。

`ai-agent-general` 的 `ToolBinder.java` 让命令 description 只承载命令自身语义，工具组说明保存在 `GeneralToolDefinition.META_INTERNAL_TOOLKIT_CONTEXT`。`InitialPromptAssembler.java` 从经权限、skill scope 与声明审计准入的 catalog 按工具组装配一次共享说明，不附加完整命令清单，也不让已拒绝的工具组贡献上下文。组级语义保持在既有 system prompt 中，不新增规则提示协议。
