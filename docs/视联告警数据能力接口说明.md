# 视联告警数据能力接口说明

## 1. 当前结论

`rule-engine-manager-ui` 通过 `alarm:device-monitoring` 与 `alarm:vision-monitoring` 两个 Provider 对外提供告警数据能力。视联能力固定查询 `vision` 来源，设备能力固定查询设备告警口径，调用方不再拼装后端查询 DSL。

- owning module：`ui/modules/rule-engine-manager-ui`
- version：`1`
- 默认时间范围：当天
- 调用方不传 `source`、`terms`、`sorts`、`termType` 或后端聚合表达式
- 实时告警使用 `poll`，本次不新增 WebSocket 连接

### 当前分支迁移计划

- 目标：由 `rule-engine-manager-ui` 承接设备告警、视联告警和统一告警摘要/列表能力的前端注册，确保 `alarm-ui` 删除后能力仍可独立加载。
- 影响范围：`modules/rule-engine-manager-ui/register.ts`、告警数据能力 Provider/service/types、自包含请求封装及中英文能力说明。
- 不做：不修改 `jetlinks-web-core` 能力协议，不改 `visualization-manager-ui` 数据面板，不改后端接口，不引入尚未注册的事件分析草稿能力。
- 实施：迁入已经联调过的 `deviceMonitoring` 与 `visionMonitoring` Provider，并保持现有 capability ID、参数和返回结构不变。
- 风险：接口可用性受当前登录态、资产权限和环境告警样本影响；轮询必须沿用运行时取消信号，避免预览销毁后继续请求。
- 验证：检查 Provider 清单与实际 source 一致，执行定向类型检查、locale JSON 解析和 `git diff --check`，再在现有测试大屏验证真实请求、渲染、重新加载及轮询。

## 2. 能力目录

### 2.1 设备告警

| DataSource ID | 用途 | 参数 |
| --- | --- | --- |
| `alarm.device.summary` | 设备告警总览 | `startTime`、`endTime` |
| `alarm.device.active.ids` | 当前告警设备 ID | 无 |
| `alarm.device.rank` | 设备告警排行 | `startTime`、`endTime`、`limit` |
| `alarm.device.list` | 设备告警列表 | 分页、时间、状态、设备和等级参数 |

### 2.2 视联与统一告警

| DataSource ID | 用途 | 参数 |
| --- | --- | --- |
| `alarm.vision.summary` | 今日告警总览 | `startTime`、`endTime` |
| `alarm.vision.trend` | 告警趋势 | `startTime`、`endTime` |
| `alarm.vision.type.distribution` | 告警类型分布 | `startTime`、`endTime`、`limit` |
| `alarm.vision.level.distribution` | 告警等级分布 | `startTime`、`endTime` |
| `alarm.vision.scene.distribution` | 告警场景分布 | `startTime`、`endTime` |
| `alarm.vision.scene.rank` | 告警场景排行 | `startTime`、`endTime`、`limit` |
| `alarm.vision.list` | 实时/历史告警 | `pageIndex`、`pageSize`、`startTime`、`endTime`、`state`、`sceneId`、`algorithmId`、`level` |
| `alarm.vision.level.trend` | 分等级告警趋势 | `startTime`、`endTime` |
| `alarm.vision.handling.trend` | 告警处理效率趋势 | `startTime`、`endTime` |
| `alarm.vision.channel.rank` | 告警通道排行 | `startTime`、`endTime`、`limit` |
| `alarm.vision.ai-review.summary` | AI 复核统计 | `startTime`、`endTime`、`spaceId` |
| `alarm.event.summary` | 物联与视联告警摘要 | 无 |
| `alarm.event.list` | 物联或视联告警列表 | 分页、时间、状态、等级及来源（默认物联） |

分页统一返回 `data`、`total`、`pageIndex`、`pageSize`。时间均为 Unix 毫秒，数据面板按时间选择器展示；状态仅支持 `active`、`handled`。设备条件使用公共设备选择器，AI 复核的空间范围使用 `space.area.options` 区域树。

## 3. 接口定义

### 3.1 告警总览 `alarm.vision.summary`

```json
{
  "data": {
    "total": 36,
    "active": 12,
    "handled": 24,
    "handledRate": 66.67,
    "alarmCount": 36,
    "alarmCameraCount": 8,
    "sampleTime": 1785283200000
  }
}
```

该能力只提供告警域指标。摄像头总数、在线率和异常摄像头数量由 `vision.camera.summary` 提供，不在此处强行合并。

### 3.2 告警趋势 `alarm.vision.trend`

```json
{
  "data": [
    { "timestamp": 1785283200000, "count": 8 }
  ]
}
```

时间桶由告警模块根据请求时间范围自动选择，调用方不传聚合粒度。

### 3.3 告警场景分布 `alarm.vision.scene.distribution`

场景名称由当前权限范围内的 AI 场景树补全，并保留告警数量为零的场景。

```json
{
  "data": [
    {
      "sceneId": "intrusion",
      "sceneName": "区域入侵",
      "count": 12
    }
  ]
}
```

### 3.4 告警列表 `alarm.vision.list`

`pageIndex` 默认 `0`，`pageSize` 默认 `20`、最大 `200`。

```json
{
  "data": [
    {
      "alarmId": "alarm-001",
      "typeId": "intrusion",
      "typeName": "区域入侵",
      "channelId": "channel-001",
      "channelName": "园区东侧摄像头",
      "location": "园区A区",
      "level": 1,
      "levelText": "紧急",
      "state": "active",
      "stateText": "未处理",
      "content": "检测到人员进入限制区域",
      "alarmTime": 1785283200000,
      "handleTime": null
    }
  ],
  "total": 1,
  "pageIndex": 0,
  "pageSize": 20
}
```

## 4. 实现与验证

实现复用既有设备/视联告警查询、等级趋势和场景聚合服务；`alarm.vision.trend` 在等级趋势之上汇总总量，告警总览兼容增加 `alarmCount` 与 `alarmCameraCount`。代码入口为 `dataCapabilities/deviceAlarmProvider.ts`、`dataCapabilities/visionAlarmProvider.ts`、相关 service 与 types、`register.ts` 和中英文 locale。

修改能力契约后应执行数据能力专项测试、目标模块构建、中英文 JSON 解析和 `git diff --check`；真实接口仍需在带登录态及对应资产权限的环境中联调。
